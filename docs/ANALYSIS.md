# Анализ оригинального приложения Micro

## 1. Что это такое

**Micro** — учебный симулятор **микропрограммируемого процессора** (МПУ) для курса
«ЭВМ и периферийные устройства» (лабораторные работы №4 и №6). Архитектура
процессора — бит-срезная, близкая к семейству AMD Am2901 / К1804ВУ1: 16-разрядное
АЛУ, регистровый файл, сдвигатель, микропрограммное управляющее устройство (МПУ)
с памятью микрокоманд, стеком адреса возврата и таблицей дешифрации кода операции.

История версий:

| Версия | Технология | Расположение |
|---|---|---|
| «Micro classic» | Delphi (исходников нет, только exe) | `D:\Projects\Micro\bin\Micro classic.exe` |
| Micro (актуальная) | C# / WPF, .NET Framework 4.7.2, MVVM | `D:\Projects\Micro\` |

Данный документ описывает C#-версию (она функционально надмножество Delphi-версии
и должна быть воспроизведена в Rust), а также форматы файлов, общие для обеих версий.

## 2. Структура C#-проекта

```
Models/
  CpuState.cs               — ядро: исполнение микрокоманд, состояния ЦП, трасса
  MicroProgramMemory.cs     — память микрокоманд (64 ячейки) + MicroCommand (19 полей)
  RegisterMemory.cs         — 31 регистр (строковые ключи), индексный доступ 0..17
  RamMemory.cs              — ОЗУ 1024 байта, побайтовый и пословный (LE) доступ
  AddressTranslationTable.cs— таблица дешифрации: 20 строк (адрес + 16-симв. маска)
  NotifyPropertyChangedStack.cs — стек возврата с уведомлениями для UI
ViewModels/                 — MVVM: команды, диалоги, загрузка/сохранение
Views/                      — XAML-окна и вкладки
Infrastructure/             — команды, конвертеры, behaviors, сервисы (диалоги, темы, настройки, обновления)
Resources/                  — схемы процессора (PNG), словари тем, иконки
```

## 3. Модель процессора

### 3.1 Регистры (31 шт.)

Порядок следования (индексы используются полями MA/MB микрокоманды и UI):

| Индекс | Имя | Назначение |
|---|---|---|
| 0–15 | AX, CX, DX, BX, SP, BP, SI, DI, CS, SS, DS, ES, IP, PSW, RGK, RW | РОНы и видимые регистры (доступ по полям A/B/reg1/reg2/r/m) |
| 16 | RFI | регистр флагов «текущий» |
| 17 | RFD | регистр флагов «сохранённый» (записывается при F=1) |
| 18 | RGQ | рабочий регистр (сдвиговый Q) |
| 19 | ARAM | адрес ОЗУ |
| 20 | RGR | регистр чтения ОЗУ |
| 21 | RGW | регистр записи ОЗУ |
| 22 | RACT | счётчик повторов (RPCT) |
| 23 | CMK | счётчик микрокоманд |
| 24 | MUAD | (адрес МПУ; не используется в симуляции, но сохраняется) |
| 25 | STP | глубина стека (отображается) |
| 26 | ERROR | (сохраняется в .RG) |
| 27 | RGA | вход A АЛУ |
| 28 | RGB | вход B АЛУ |
| 29 | ALU | выход АЛУ (не регистр в железе, показывается для наглядности) |
| 30 | SDA | выход сдвигателя |

Кодирование полей микрокоманды: `reg1` = биты 10:8 RGK, `reg2` = биты 5:3 RGK,
`r/m` = биты 2:0 RGK.

### 3.2 Микрокоманда (19 полей)

`A, B (0..F)` — номера регистров; `MA, MB (0..3)` — выбор источника: 0=поле A/B,
1=reg1, 2=reg2, 3=r/m; `MEM (0..7)` — 0–3 = нет, 4 = чтение байта, 5 = чтение слова,
6 = запись байта, 7 = запись слова; `SRC (0..7)` — коммутатор операндов;
`SH` — сдвигатель (0,1,2,3,4,5,6,8,A,E); `N (0..F)` — величина сдвига;
`ALU (0..F)` — функция АЛУ; `CCX (0..3)` — перенос C0 (0=0, 1=1, 2/3=C из RFI);
`F (0..1)` — сохранить флаги в RFD; `DST (0..4)` — приёмник результата (0=нет,
1=dst=RGR, 2=старший байт dst=RGR<<8, 3=младший байт dst=RGR>>8, 4=dst=SDA);
`WM (0..3)` — 1=RGW=SDA, 2=ARAM=SDA, 3=ARAM=RGB; `JFI (0..5)` — управление
условием перехода (бит0 — инверсия, бит1 — источник RFD/RFI, бит2 — безусловный,
5=останов); `CC (0..7)` — условие перехода (P/Z/N/V/C/L/JLE/JBE); `CHA (0..7)` —
операция МПУ (0=CMK←0, 1=CJS, 2=JMAP, 3=CJP, 4=RPCT, 5=CRTN, 6=LDCT, 7=CONT);
`CONST (0..FFFF)` — константа/адрес перехода; `Comment` — произвольный текст
(только в .XMEM).

### 3.3 АЛУ (16 функций, 32-битная арифметика)

```
0: 0            1: S-R-1+C0     2: R-S-1+C0     3: R+S+C0
4: S+C0         5: ~S+C0        6: R+C0         7: ~R+C0
8: S            9: R&S          A: R&~S         B: ~(R&S)
C: R|S          D: ~(R|S)       E: R^S          F: ~(R^S)
```

Операнды: (r,s) выбираются полем SRC: 0=(0,0), 1=(RGA,RGB), 2=(RGA,RGQ),
3=(RGA,RGR), 4=(RGA<<1, RGB), 5=(CONST,RGB), 6=(CONST,RGR), 7=(CONST,RGQ).

Промежуточный результат — 32-битный; регистр ALU — младшие 16 бит.

### 3.4 Флаги (RFI)

- N (бит 7) = старший бит ALU; Z (бит 6) = (ALU==0);
- C (бит 0) = бит 16 32-битного результата — только для арифметических функций (ALU<9);
- V (бит 11) = N xor C (в реализации: `((RFI<<4) ^ (RFI<<11)) & 0x800`);
- P (бит 2) = чётность по 16 битам ALU (XOR всех бит; 1 = нечётное число един);
- логические операции (ALU>=9) сбрасывают C и V;
- при F=1 весь RFI копируется в RFD.

### 3.5 Сдвигатель (SH)

| Код | Операция |
|---|---|
| 0 | SDA = ALU |
| 1 | арифметический сдвиг ALU вправо на N |
| 2 | логический сдвиг ALU вправо на N |
| 3 | АС ALU вправо + RGQ вправо (RGQ = RGQ>>N \| ALU<<(16-N)) |
| 4 | ЛС ALU вправо + RGQ вправо |
| 5 | RGQ логически вправо на N |
| 6 | RGQ = ALU, SDA = ALU |
| 8 | логический сдвиг ALU влево на N |
| A | ЛС ALU/RGQ влево: SDA = ALU<<N \| RGQ>>(16-N), RGQ <<= N |
| E | расширение знака байта (бит7 ALU → 0xFF00) |

### 3.6 Управляющее устройство (CHA) и условия

Условие (CC) вычисляется по RFI или RFD (бит 1 JFI) с инверсией (бит 0 JFI);
JFI&4 = безусловный переход. Коды CC: 0=P, 1=Z, 2=N, 3=V, 4=C, 5=N^V (JL),
6=Z|(N^V) (JLE), 7=C|Z (JBE).

CHA: 0 → CMK=0 (выборка следующей команды); 1 → CJS: push(MK.адрес+1), CMK=CONST
по условию; 2 → JMAP: дешифрация RGK по таблице преобразования адресов (первая
строка с совпадением по маске X → адрес); 3 → CJP: CMK=CONST по условию;
4 → RPCT: если RACT≠0, RACT--, CMK=CONST, иначе CMK++; 5 → CRTN: pop в CMK по
условию; 6 → LDCT: RACT=CONST, CMK++; 7 → CONT: CMK++.

Остановка: JFI=5 у выполненной МК, либо CMK > 0x3F при попытке исполнения.
Стек возврата в C#-версии не ограничен по размеру (в отличие от классической
«микры», где он аппаратный).

### 3.7 Режимы исполнения

- **Рестарт** — CMK=RFI=RFD=RGA=RGB=ALU=SDA=0, стек и трасса очищаются (РОНы не сбрасываются);
- **Шаг** — исполнить одну микрокоманду;
- **Команда** — исполнять МК, пока не выполнится МК с CHA=0 (выборка следующей команды), затем пауза;
- **Пуск/Стоп** — непрерывное исполнение с периодом ~1 МК/мс (Task.Delay(1)),
  повторное нажатие — пауза;
- **Трасса** — после каждой МК и при рестарте снимается снимок 27 величин
  (CMK, 16 РОНов, RW…RACT в порядке из §3.1), экспорт в CSV с разделителем `;`
  (столбцы: CMK;AX;…;RGQ;N;Z;V;C;P;ARAM;RGR;RGW;RACT).

## 4. Форматы файлов (совместимость с Delphi-версией)

Все форматы текстовые, кодировка — Latin-1/UTF-8 (значения < 0x80, поэтому совпадают).
Управляющие символы: `\x01` (SEP), `\x02` (STX), `\x04` (EOT), `\x10` (DLE).

### .MEM (микропрограммная память, Delphi-совместимый)
17 полей на МК: `SEP A SEP B SEP MA SEP MB SEP MEM SEP SRC SEP SH SEP N SEP ALU
SEP CCX SEP F SEP DST SEP WM SEP JFI SEP CC SEP CHA EOT CONST` — всё HEX
(по одному символу на поля, CONST — 4 символа). При загрузке SEP/EOT заменяются
пробелами и сплит по пробелам.

### .XMEM (расширенный, C#-версия)
18 полей на МК через `\x01`, 18-е — комментарий, строки разделены `\n`.
Загрузка: сплит по `\x01` и `\n`, 18 полей на строку.

### .RAM (ОЗУ)
1024 байта: `STX + 2 hex-цифры` на каждый байт.

### .RG (регистры), ровно 154 символа
`EOT AX EOT BX EOT CX EOT DX` + `EOT reg[i]` для i=4..15 + `STX 00 STX 00`
(RFI/RFD не сохраняются специально) + `EOT RGQ EOT CMK EOT MUAD EOT STP
EOT ERROR EOT RACT` + `\0 \x01 \x01` + `EOT ARAM EOT RGR EOT RGW` + 20 нулевых
символов. При загрузке читаются фиксированные смещения (см.
`RegistersViewModel.LoadRegisters`): AX@1, BX@6, CX@11, DX@16, reg[i]@i*5+1,
RGQ@87, CMK@92, MUAD@97, STP@102, ERROR@107, RACT@112, ARAM@120, RGR@125, RGW@130.
RFI/RFD при загрузке сбрасываются в 0 (несовместимость флагов с классической
микрой, оставлена намеренно).

### .TTA (таблица преобразования адресов), ровно 480 символов
20 строк по 24 символа: `STX + 2 hex-адреса + DLE + 16-симв. опкод (0/1/X) + "MaxA"`.
При загрузке: адрес @ i*24+1 (2 символа), опкод @ i*24+4 (16 символов).

## 5. Интерфейс

Окно 1000×720 (мин.), заголовок «Микропрограммируемый процессор». Тема
светлая/тёмная, переключение кнопкой в правом верхнем углу, выбор сохраняется.

- **Вкладка «Работа»** — принципиальная схема процессора (PNG 1305×807) с
  наложенными полями значений регистров (AX…RW, ARAM, RGA, RGB, ALU, SDA, RGQ,
  RGR, RGW, CMK, RACT, RGK в бинарном виде, STP, индикатор STOP, содержимое
  стека, таблица флагов N/Z/V/C/P для RFI и RFD). Сверху — таблица «Выполнена /
  Следующая» микрокоманды. Снизу — кнопки: Рестарт, Пуск/Стоп, Шаг, Команда,
  Сохранить трассу. Регистры, изменившиеся при исполнении последней МК,
  подсвечиваются (подсветка снимается при начале следующей МК).
- **Вкладка «Данные» → «Микропрограммная память»** — редактируемая таблица 64 МК
  (все поля HEX + комментарий), контекстное меню вставки/удаления МК (со сдвигом),
  кнопки Загрузить/Сохранить (.XMEM/.MEM).
- **Вкладка «Память»** — редактор ОЗУ: режимы Байты/Слова (таблица 64×16 + колонка
  ASCII в байтовом режиме), «Перейти по адресу (HEX)», Загрузить/Сохранить (.RAM).
- **Вкладка «Регистры»** — группы: РОНы (16), Регистры флагов (RFI, RFD),
  Рабочий регистр (RGQ), Регистры блока МПУ (CMK, MUAD, STP, ERROR, RACT),
  Регистры ОП (ARAM, RGR, RGW); ввод HEX; Загрузить/Сохранить (.RG)/Сброс.
- **Вкладка «Таблица преобразования адресов»** — 20 строк (начальный адрес HEX +
  код операции 0/1/X), Загрузить/Сохранить (.TTA).
- **Статусная строка** — версия + ссылка при наличии обновления (GitHub releases).

## 6. Прочее поведение

- **Настройки**: XML `%LOCALAPPDATA%\Micro\Micro.config.xml` (фолбэк — рядом с exe),
  единственное поле — тема. Повреждённый файл пересоздаётся.
- **Проверка обновлений**: GET
  `https://raw.githubusercontent.com/I-Kerosin-I/Micro-releases/main/latestversion.txt`,
  сравнение с версией сборки, гиперссылка на страницу релизов.
- **Предупреждение при выходе** при несохранённых изменениях (отдельно для МПП,
  ТТА, ОЗУ) с возможностью сохранить/выйти без сохранения/отменить.
- **Валидация ввода**: поля МПП/памяти/регистров принимают только HEX-символы;
  ошибки исполнения (обращение за пределы ОЗУ, неудачная дешифрация, pop из
  пустого стека) — через MessageBox.
- **Известные особенности/дефекты C#-версии** (учтены при переносе):
  - pop из пустого стека не останавливает ЦП и не инкрементирует CMK (потенциальное зависание);
  - неудачная дешифрация команды (JMAP) не останавливает ЦП;
  - `MEM` при выходе за пределы ОЗУ показывает MessageBox, но не прерывает МК;
  - доступ к регистру по имени с невалидным ключом упадёт (защиты нет);
  - SH=7,9,B..D, F — «Invalid SH value» (исключение в рантайме);
  - трасса не ограничена по размеру.
