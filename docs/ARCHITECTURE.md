# Архитектура Rust-версии Micro

## 1. Технологический стек

| Компонент | Выбор | Обоснование |
|---|---|---|
| Язык | Rust (edition 2021) | по заданию |
| GUI | `egui` 0.37 + `eframe` 0.37 (рендерер **glow**) | immediate-mode UI без WebView/Chromium; glow заметно легче wgpu и достаточен для 2D-интерфейса (требование «wgpu где уместно» — здесь не уместно: ни 3D, ни шейдеров) |
| Диалоги файлов | `rfd` | нативные диалоги Windows/Linux |
| Таблицы | `egui_extras` (Table) | большие таблицы (МПП 64×19, ОЗУ 64×17) с виртуализацией |
| Декодирование PNG схемы | `image` (только `png`) | схемы процессора из оригинала |
| Настройки | `serde` + `serde_json` + `dirs` | JSON в стандартном каталоге конфигурации ОС |

Запрещённые по заданию технологии (Electron, Tauri/web-фронтенд, WebView) не используются.

## 2. Структура workspace

```
rust/
├── Cargo.toml            # workspace
├── micro-core/           # ядро: без зависимостей от GUI
│   └── src/
│       ├── lib.rs        # публичный API ядра
│       ├── register.rs   # перечисление 31 регистра, имена, индексация
│       ├── microcommand.rs # MicroCommand: поля, значения по умолчанию, валидация
│       ├── mpm.rs        # память микрокоманд (64 ячейки), вставка/удаление
│       ├── ram.rs        # ОЗУ 1024 байта, байт/слово (LE)
│       ├── translation.rs# таблица дешифрации (20 строк)
│       ├── cpu.rs        # исполнение МК, состояния, трасса, события
│       ├── formats.rs    # .MEM/.XMEM/.RAM/.RG/.TTA (чтение/запись)
│       └── trace.rs      # снимки состояния, экспорт CSV
└── micro-app/            # GUI (eframe)
    └── src/
        ├── main.rs       # запуск, иконка, настройки окна
        ├── app.rs        # корневой App: навигация, панель управления, тосты
        ├── settings.rs   # сохранение настроек (JSON)
        ├── theme.rs      # дизайн-система: палитры, стили, типографика
        ├── widgets/      # переиспользуемые компоненты (hex-поля, тосты, кнопки)
        └── views/        # cpu (схема), mpm, ram, registers, translation
```

## 3. Разделение ответственности

- **micro-core** не знает о GUI: никаких egui-типов. Вход — структуры данных
  (`MicroCommand`, `RamMemory`, …), выход — значения и события. Полностью
  покрывается юнит-тестами, в т.ч. на файлах лабораторных работ.
- **micro-app** — только представление и ввод. Исполнение программы: кадр UI
  забирает у ядра квант времени (N микрокоманд, ограничение по времени ~4 мс),
  затем отрисовывает состояние; между кадрами `request_repaint_after`.

## 4. Модель событий ядра

`CpuState::step()` возвращает `StepReport { executed: MicroCommand, events: Vec<CpuEvent>, state }`,
где `CpuEvent` — { `MemoryOutOfBounds`, `DecodeFailed`, `StackEmpty`, `Halted`, … }.
UI отображает события тостами. Это заменяет `MessageBox.Show` из C# и убирает
блокировки UI-потока.

## 5. Состояние UI

- Навигация: боковая панель (Работа / Микропрограмма / Память / Регистры / Дешифратор).
- Панель управления (transport bar) внизу окна видна на всех вкладках:
  Рестарт · Пуск/Стоп · Шаг · Команда · Сохранить трассу · индикатор состояния · CMK/STP.
- Каждая вкладка владеет своими локальными состояниями (режим байты/слова,
  адрес перехода, активная ячейка редактирования).
- Признаки «изменено» (МПП/ОЗУ/ТТА) — в ядре, как в оригинале; используются
  для предупреждения при выходе и маркеров в навигации.

## 6. Схема процессора на вкладке «Работа»

PNG-схемы оригинала (1305×807, тёмная и светлая) встраиваются в бинарник
(`include_bytes!`), декодируются в текстуру при старте. Значения регистров
рисуются поверх изображения поверхностным слоем egui по нормированным
координатам (пересчёт из XAML-канвы 1305×807), что даёт идентичную схему при
масштабировании окна.

## 7. Совместимость

Форматы .MEM/.XMEM/.RAM/.RG/.TTA реализованы побайтово совместимыми с оригиналом
(см. `docs/ANALYSIS.md` §4) — файлы лабораторных работ открываются без конверсии.
Проверяется юнит-тестами на реальных файлах из репозитория оригинала.

## 8. Кроссплатформенность

- Пути: `dirs::config_dir()` для настроек; разделители — только `PathBuf`;
- шрифты: встроенные в egui (Ubuntu-Light/DejaVu Mono) содержат кириллицу —
  системных шрифтов не требуется;
- диалоги: `rfd` (IFileDialog на Windows, GTK-порты на Linux);
- Linux: eframe с фичами `x11` + `wayland`;
- прочие платформозависимые места отсутствуют (нет системных вызовов вне библиотек).

## 9. Профиль сборки

```toml
[profile.release]
opt-level = 3
lto = "thin"
codegen-units = 1
strip = true
panic = "abort"
```

Целевой размер exe — < 20 МБ (ожидаемо ~8–12 МБ при glow-рендерере).
